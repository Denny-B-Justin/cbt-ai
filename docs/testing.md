# Testing

```bash
pip install -r requirements-dev.txt
playwright install chromium            # only for the browser tests
pytest                                 # all (about 90 s)
pytest -m "not ui"                     # no browser (about 10 s)
pytest tests/test_pipeline.py -k greener
python tests/live_check.py             # the only thing that calls a real provider; needs your API key
```

## Principle

Automated tests never touch the network. The model is replaced in two ways, so every layer above it runs for real:

| Stand-in | Replaces | Used by |
|---|---|---|
| `tests/fake_llm.py::FakeProvider` | `ai/<provider>.py` (in process) | pipeline, UI and export tests. Reads `Title | amount` rows from the prompt and answers the guiding questions from a few climate words (solar, flood, …); supports `delay`, `fail_first`, `error`. |
| `tests/fake_llm_server.py` | the OpenAI, Anthropic, Gemini and Mistral APIs | `test_llm.py`: the real SDKs (openai, anthropic, google-genai, mistralai) talk to a local server, through `<PROVIDER>_BASE_URL`, that returns queued successes and errors in each provider's format |
| `Scripted` provider in `test_tasks.py` | provider with arbitrary answers | task-level behaviour: splitting, second passes, normalisation |

`tests/conftest.py` gives each test a fast rate limiter, dummy API keys with an address where nothing answers (so no
test can reach a real provider), an empty session store and the fixtures
`fake_ai`, `use_provider`, and the sample documents. Sample documents in `docs/samples/` are fictional and generated by
`docs/samples/make_samples.py` (reportlab, python-docx).

## What each file covers

| File | Covers |
|---|---|
| `test_formatting.py` | missing values, numbers and percentages, money in the document's unit, text helpers |
| `test_documents.py` | PDF and Word reading, table rows, header/footer removal, scan notes, chunk coverage and order, PDF attachments, splitting, rejected files (type, size, password, page count) |
| `test_lines.py` | amount parsing, merge by code, subtotals, folding, view choice, duplicates, negatives |
| `test_tags.py` | consistent verdicts (the four levels only on tagged lines, snapping, service costs, liveable wording, Q2 without Q1), the tagging instructions, CM / CA / CB and the 50/50 split, "Not assessed" lines |
| `test_metrics.py` | shares by amount and by lines, missing amounts, grouped tables adding up, rubric |
| `test_ratelimit.py` | spacing, adaptive slow-down, retry schedule, give-up, cancel during back-off |
| `test_llm.py` | settings (three latest and one older model per provider, only providers with a key offered, default model, `GOOGLE_API_KEY`, unknown models, no keys), the key and the chosen model reaching each API, request shape per provider (JSON schema, PDF parts, no PDF for Mistral, reasoning and thinking settings), Anthropic's fallback from structured outputs to a forced tool to plain JSON, refused settings and output length, too-large requests, error mapping per HTTP status, no SDK retries, advised wait, cut-off and empty answers, unreachable APIs, the whole path through `ai.client` |
| `test_tasks.py` | the four tasks incl. split-on-truncation, missing-id second pass, fatal errors, normalisation |
| `test_pipeline.py` | full analyses of the samples, failure messages, cancellation, comparison guard and fallback |
| `test_session.py` | lifecycle, sweeping, job states, cancel semantics, busy limit |
| `test_export.py` | workbook sheets, headings, formula neutralisation, file names |
| `test_ui.py` | headless Chromium against a real server thread: navigation, both flows, loader behaviour, cancel, errors, downloads, session end on page hide/close/refresh, no technical wording, phone widths |

## What is not covered

- **Real model behaviour.** Tag quality and robustness to unusual layouts depend on the model. Use `tests/live_check.py`, then
  open the results table of a few real budgets and read the reasons.
- **Real quota behaviour** (free-tier limits differ per model and change over time).
- **Large documents under load** (hundreds of pages, many visitors). The code paths are exercised with multi-section
  documents and the busy limit, but not with production volumes.

Try real documents without spending quota (stand-in model, so only reading/cleaning/UI are exercised):

```bash
CBT_REAL_DOCS=/path/to/folder/with/pdfs pytest tests/test_pipeline.py -k real_documents
```

## Writing new tests

- Prefer `Scripted` or a `FakeProvider` subclass over mocking internals. They go through `ai.client`, so pacing and retry code runs.
- Tests that sleep must patch `ai.ratelimit._sleep` (see `no_waiting` in `test_pipeline.py`); real back-off is minutes long.
- UI tests wait for specific elements (`wait_for_selector`, `expect(...)`), not fixed sleeps. Plotly loads lazily, so wait for
  `.js-plotly-plot` before counting charts.
- When a test asserts a user-facing sentence, import it from the code (for example `ui.PRIVACY_TEXT`) so wording changes do not break it.
